Network Integrity Monitor

Periodically checks for DNS poisoning, ARP spoofing (gateway-MAC watch + subnet impersonation) and rogue DHCP servers in the background, and sends a Pushover alert if the verdict goes bad. With extended monitoring it also rotates the full passive-scanner suite — STP root-hijack, DTP VLAN-hop, FHRP/OSPF/EIGRP/IS-IS/BGP routing hijack & injection, SMB poisoning, NTLM relay/coercion, IGMP/IPv6/ICMP/NTP/SNMP/Cert and RA-Guard posture — a few per cycle so each stays light. IPv6 RA Guard (host first-hop hardening)

                        
The defence half of IPv6 first-hop security. Where IPv6 First-Hop Watch (Switch & L2/L3) detects a rogue RA / DHCPv6 / ICMPv6-Redirect on the wire, RA Guard audits this host's own IPv6 settings so a rogue first-hop can't take effect even if it reaches you — and can harden them in one click. It never sends a packet; it reads /proc/sys/net/ipv6/conf and the routing table.

                        
Grades each interface on accept_redirects (accepting an ICMPv6 Redirect lets any on-link host reroute your traffic — a Layer-3 MITM), accept_ra_rtr_pref (honouring RA Router-Preference lets a rogue "pref high" RA jump ahead of the real router), and accept_ra, and shows which IPv6 gateway the host has actually accepted. Harden sets the two safe sysctls (accept_redirects=0, accept_ra_rtr_pref=0) live and persists them to /etc/sysctl.d; accept_ra is left untouched so SLAAC connectivity keeps working.

                        

                            
                            
                        

                        

                    

                    
                    

                        
NTP Watch (rogue time source · clock injection)

                        
NTP (UDP/123) is the network's clock of record. A rogue NTP server that answers clients — or broadcasts — with the wrong time silently poisons every downstream timestamp: audit logs, TLS / Kerberos validity windows, MFA/TOTP codes, and lab-result / chain-of-custody records. On a precision-critical segment (medical, finance, industrial) a few seconds of skew is a real incident — yet nobody watches 123. Detection-only — it never sends an NTP query.

                        
Passively captures NTP and flags time-injection (a source whose served time disagrees with the segment consensus / local clock), a rogue server (answering but not in the baseline), a Kiss-o'-Death (stratum-0 sync-DoS), stratum spoofing (a forged Stratum-1/GPS claim), a rogue broadcast time source, mode 6/7 monlist recon/amplification, and anomalies (implausible root dispersion, leap-alarm, refid loop). First scan learns the trusted time source(s) (data/ntp_watch.json); "Trust current" re-learns.

                        

                            
                            
                            
                            
                        

                        

                    

                    
                    

                        
SNMP Watch (v1/v2c cleartext community exposure)

                        
SNMP v1 and v2c authenticate with a plaintext "community string" — effectively a device password sent in the clear on every request. Anyone sniffing the segment harvests it: the read community (often the default public) exposes the full device config, and a write community — seen on a SetRequest — lets whoever captured it reconfigure the device (routes, ACLs, interfaces). v3 (USM auth + privacy) fixes this. Detection-only — it never sends an SNMP request.

                        
Passively captures SNMP (UDP 161/162) and flags write-exposed (a cleartext SetRequest), cleartext v1/v2c community exposure (worse for default strings like public/private), SNMP amplification (GetBulk with huge max-repetitions — a reflection-DDoS vector), and enumeration (a host walking the MIB). Only v3 reads clean. First scan learns the segment's agents + community strings (data/snmp_watch.json) so later scans highlight new exposure; "Trust current" re-learns.

                        

                            
                            
                            
                            
                        

                        

                    

                    
                    

                        
Cert Watch (certificate & TLS hygiene)

                        
Internal networks are full of TLS services — router/switch admin UIs, NAS boxes, hypervisors, printers, IoT — with certificates nobody audits: long expired, self-signed, hostname-mismatched, or signed with weak crypto. A certificate checker is inherently active — it must complete a TLS handshake to read the cert (TLS 1.3 encrypts it, so passive sniffing can't). It fetches the cert even when validation fails, so it can tell you exactly why it's invalid.

                        
Grades each target for expired / not-yet-valid / self-signed / untrusted (not in the system CA store) / hostname-mismatch / weak-crypto (SHA-1/MD5, RSA<2048, weak cipher) / deprecated-tls (TLS 1.0/1.1) / expiring (<21 days). Type targets as host or host:port, and/or tick Discover to passively find the TLS servers on the segment first (server IP:port + SNI). A learned fingerprint baseline (data/cert_watch.json) flags a cert that changed between scans (rotation or possible MITM); "Trust current" re-learns.

DHCP Guardian

                    
DHCP-snooping-style monitor — detection-only, never runs a DHCP server. Detects rogue / fake DHCP servers (a second server, or one handing out the wrong gateway/DNS — a turnkey MITM) and DHCP starvation (pool-exhaustion floods). DHCP Snooping (inline bridge)

                        
                    

                    
Enterprise-grade, detection-only. With two NICs bridged inline (Pi sits between the client segment and the uplink), every DHCP packet transits the box per port. A DHCP server reply (OFFER/ACK) arriving on the untrusted (client) port is a rogue server by definition — zero false positives — and OFFER/ACKs build a live binding table (MAC ↔ IP ↔ lease ↔ port).

IPv6 First-Hop Watch (rogue RA / DHCPv6 · mitm6)

                    
The most-overlooked LAN attack today. Every modern OS ships with IPv6 on and prefers it — even on "IPv4-only" networks nobody manages. A rogue Router Advertisement or DHCPv6 server silently becomes the segment's gateway/DNS (the SLAAC / mitm6 attack), and a tech watching only IPv4 / ARP / DHCP never sees it. Detection-only — never sends an RA, never answers a solicit.

                    
Passively captures ICMPv6 RA/RS/Redirect + DHCPv6 and flags a rogue RA (new gateway, injected DNS/prefix, pref high, or router-lifetime 0), a rogue DHCPv6 server (mitm6's DNS-takeover signature), an RA flood, and conflicting routers. First scan learns the trusted router(s)+server(s) (data/ipv6_watch.json); "Trust current" re-learns. Mitigate with switch RA-Guard (RFC 6105) / DHCPv6 snooping.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
NDP Watch (IPv6 neighbor spoofing · the v6 ARP-poison twin)

                    
The IPv6 twin of ARP Watch. ARP Watch catches IPv4 cache poisoning and IPv6 First-Hop Watch catches rogue RA / DHCPv6 — but neither catches the direct v6 analogue of ARP poisoning: a forged Neighbor Advertisement claiming someone else's address, which poisons every neighbour's ND cache and puts an attacker on-path (parasite6). On any dual-stack LAN this is the open door a v4-only defender never sees. Detection-only — never sends an NA, never answers a solicit.

                    
Passively captures ICMPv6 Neighbor Solicitation / Advertisement (135/136) and flags spoofed (two MACs claiming one address, the default router advertised by a rogue MAC, or a learned host's owner-MAC changing), dad-dos (one MAC answering every Duplicate Address Detection probe — dos-new-ip6, so no host can pick an address), and an NA flood. First scan learns the trusted target→MAC bindings + default router (data/ndp_watch.json); "Trust current" re-learns. Mitigate with switch IPv6 Snooping / ND Inspection (SAVI, RFC 6620).

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
ICMP Watch (ICMP redirect · L3 route injection)

                    
The ICMP Redirect (type 5) is the classic Layer-3 man-in-the-middle: any host on the segment can forge a redirect that looks like it came from the gateway and tell a victim "for destination X, use next-hop Y instead" — steering that traffic through the attacker. No ARP poisoning, no gateway compromise needed, and many hosts honour redirects by default. Detection-only — it never sends an ICMP packet.

                    
Passively captures IPv4 ICMP and flags a redirect steering traffic to a non-gateway next-hop (or from a non-gateway source), a rogue IRDP router advertisement (type 9 gateway injection), an ICMP flood (ping-flood / smurf), tunnelling (oversized echo payloads = covert channel / exfil), and recon (timestamp / address-mask / information requests). Compares against the host's default gateway (learned into data/icmp_watch.json); "Trust current" re-seeds. ICMPv6 redirects (type 137) are covered by IPv6 First-Hop Watch.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
IGMP Watch

                    
Passive IGMP-snooping security scanner — detection-only, never joins a group or becomes a querier. Watches the multicast control plane for storms/floods (report-flood DoS), anomalies (a rogue second querier drawing all multicast to itself, version downgrades), reconnaissance (a host enumerating many groups) and unauthorized joins (a host on an admin/globally-scoped group it shouldn't be).

                    
One short passive capture on the chosen segment. The first scan learns the current querier(s) and host→group memberships as the trusted baseline (data/igmp_watch.json); after a legitimate multicast/router change, click "Trust current".

                    

                        
                        
                        
                        
                    

                    

                


                
                

                    
TLS Watch (passive handshake observer)

                    
Passive TLS/QUIC handshake observer — detection-only, never connects. Sniffs ClientHello/ServerHello off the wire for JA4/JA4_r & JA3/JA3S fingerprints, SNI / ALPN / negotiated version & cipher, and flags certificate anomalies (expired / self-signed / weak-sig / SNI↔cert mismatch — the interception signal), weak/legacy ciphers, and a JA4 denylist. Recovers QUIC v1/v2 Initials too.

                    
One short passive capture on the chosen segment (needs a SPAN/mirror port to see other hosts). Certificate findings apply to TLS 1.2 over TCP only — TLS 1.3 and QUIC encrypt the certificate, so those show fingerprints + SNI but a black-box cert. JA4S (server fingerprint) is off by default (FoxIO License 1.1).

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
STP/BPDU Watch (spanning tree · root hijack)

                    
Passive spanning-tree security scanner — detection-only, never sends a BPDU. STP/RSTP/MSTP (and Cisco PVST+) elect a root bridge by lowest Bridge ID; BPDUs carry the election, multicast in the clear with no auth. An attacker who sends a BPDU claiming a superior root (priority 0 — Yersinia "claim root role") wins and the tree reconverges to pull traffic through them (L2 MITM). Flags root-hijack (a root superior to the baseline), rogue-bridge (a new bridge in spanning tree), bpdu-flood (reconvergence-storm DoS) and topology-change (TCN/TC churn that flushes MAC tables). Defenses are BPDU Guard on edge ports and Root Guard downstream.

                    
One short passive capture on the BPDU group MACs (IEEE 01:80:c2:00:00:00 + Cisco PVST+ 01:00:0c:cc:cc:cd). The first scan learns the current root(s) — per VLAN for PVST+ — and legitimate bridges as the baseline (data/stp_watch.json); after a legitimate topology change, click "Trust current".

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
DTP Watch (Cisco · VLAN hopping)

                    
Passive Dynamic Trunking Protocol scanner — detection-only, never sends a DTP frame. DTP auto-negotiates whether a switch port becomes an 802.1Q/ISL trunk; a port left in the default dynamic auto/desirable mode will form a trunk with anything that speaks DTP "desirable". That's the classic VLAN-hopping / switch-spoofing attack (Yersinia "enable trunking"): a rogue host trunks the port to itself and sees/injects into every VLAN. Flags vlan-hop (trunk-forming DTP from a new speaker), trunk-negotiation (a port isn't nonegotiate, so it's exploitable) and dtp-enabled (DTP present at all). DTP should never appear on an access segment.

                    
One short passive capture on the switch group MAC (01:00:0c:cc:cc:cc, DTP PID 0x2004). DTP hellos are ~30s apart, so give it a longer window. The first scan learns the current DTP speakers (real switches) as the baseline (data/dtp_watch.json); a new speaker sending trunk-forming DTP is the tell. Click "Trust current" after a legitimate switch change.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
CDP Watch (Cisco Discovery · flood / spoof / info-leak)

                    
Passive Cisco Discovery Protocol scanner — detection-only, never sends a CDP frame. CDP is on by default on every Cisco device and, unauthenticated, advertises to anyone on the wire the device hostname, full IOS version (→ known CVEs), hardware model, management IP, native VLAN, VTP domain and voice VLAN — a reconnaissance goldmine. Flags flood (Yersinia CDP flood — CAM/CPU exhaustion DoS), spoof (a new/rogue CDP speaker, incl. a fake IP phone advertising a Voice VLAN = VoIP-VLAN-hop), and cdp-enabled (surfaces exactly what CDP leaks here).

                    
One short passive capture on the switch group MAC (01:00:0c:cc:cc:cc, CDP PID 0x2000). CDP hellos are ~60s apart, so give it a longer window. The first scan learns the current CDP speakers (real switches/phones) as the baseline (data/cdp_watch.json); "Trust current" re-learns. Mitigate by disabling CDP on access ports (no cdp enable) and preferring LLDP with minimal TLVs.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
VTP Watch (Cisco · VTP bomb / VLAN-DB wipe)

                    
Passive VLAN Trunking Protocol scanner — detection-only, never sends a VTP frame. VTP syncs the VLAN database across a domain, and its whole security model rests on one number: the switch advertising the highest configuration revision wins, and every other switch overwrites its VLAN database to match. So a rogue switch — or one forged frame — carrying the domain name and a higher revision silently rewrites, and can delete, every VLAN across the entire domain: the VTP bomb, a one-frame domain-wide outage. VTPv1/2 have no per-port authentication. Flags revision-bomb (higher revision from an unexpected source), rogue-server (a new VTP speaker / different domain), and vtp-enabled (present / a legit bump from the known server).

                    
One short passive capture on the switch group MAC (01:00:0c:cc:cc:cc, VTP PID 0x2003). The first scan learns the domain, revision and VTP server as the baseline (data/vtp_watch.json); a higher revision from a source that isn't the known server is the bomb signal. Click "Trust current" after a legitimate VLAN change. Mitigate with vtp mode transparent (or VTPv3 + password), and always zero a switch's config-revision before connecting it.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
SMB Watch (SMBv1 · LLMNR/NBT-NS/mDNS poisoning · Kerberos downgrade)

                    
Passive Windows-endpoint attack-surface scanner — detection-only, one capture, three parts. Part 1 — SMBv1: the deprecated SMB dialect and the EternalBlue / WannaCry (MS17-010) vector; still lurking on legacy NAS/printers. Tells a real SMBv1 session (tree-connect / server negotiate-response) apart from a harmless multi-dialect offer. Part 2 — LLMNR/NBT-NS/mDNS poisoning: when DNS fails, Windows falls back to these broadcast/multicast name lookups; Responder/Inveigh answer with the attacker's IP and harvest NTLMv2 hashes (crack or relay). Nothing legit answers LLMNR/NBT-NS, so a host that does is a poisoner. Flags poisoning (an active Responder, incl. WPAD targeting), spoof-conflict (two hosts answering one name), SMBv1 use, and name-exposure (LLMNR/NBT-NS in use at all). Part 3 — Kerberos downgrade (tcp+udp 88): a tolerant DER reader inspects KDC traffic for kerberoast (a TGS-REQ forcing RC4 on a service SPN so the ticket is crackable — Rubeus/GetUserSPNs), AS-REP roast (an AS-REQ with no pre-auth), downgrade (the KDC issuing a DES/RC4 ticket, or a client with AES stripped), and legacy-etype exposure.

                    
One short passive capture (SMB tcp/445+139, LLMNR udp/5355, NBT-NS udp/137, mDNS udp/5353, Kerberos tcp+udp/88) — tcpdump captures, Scapy dissects. The first scan learns the accepted mDNS responders (printers/Macs), any SMBv1 hosts, and the Kerberos KDCs/realms as the baseline (data/smb_watch.json); LLMNR/NBT-NS answers and Kerberos downgrade/roasting are never trusted away. Click "Trust current" after a legitimate change. Needs Scapy (Detector Self-Test → Install Scapy).

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
Relay/Coercion Watch (NTLM relay defense)

                    
Passive NTLM-relay + authentication-coercion scanner — detection-only, the defensive counterpart to Responder-style theft (SMB Watch catches the harvest; this catches the relay and the coercion that feed it). NTLM has no channel binding by default, so a captured or coerced auth can be relayed to another host as the victim. Flags coercion-attempt — an MSRPC call forcing a host to authenticate: PetitPotam (MS-EFSRPC), PrinterBug (MS-RPRN opnum 65/66), DFSCoerce (MS-DFSNM), ShadowCoerce (MS-FSRVP) — relay-suspected (the same NTLM server challenge seen from two servers = a relay in progress), and signing-not-required (an SMB server that makes relay possible in the first place).

                    
One short passive capture on MSRPC/SMB (tcp/445 · 139 · 135). Coercion interfaces are matched by their DCE/RPC UUID in the RPC bind; NTLM challenges and SMB2 signing come from the payloads. tcpdump captures, Scapy dissects (needs Scapy). The first scan learns accepted unsigned servers as the baseline (data/relay_watch.json); coercion + relay are never baselined away. Fix: enforce SMB/LDAP signing + channel binding (EPA), patch the coercion vectors.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
LDAP Watch (Active Directory / LDAP)

                    
Passive Active Directory / LDAP observer — detection-only, never transmits. Sniffs LDAP (tcp/389, GC/3268), LDAPS/GC-S (636/3269) and connectionless CLDAP (udp/389), reassembles TCP flows, and decodes the BER/ASN.1 LDAPMessage with a hand-rolled definite-length decoder. Flags cleartext credentials (a simple/SASL-PLAIN bind whose password is recoverable from the capture), anonymous / unauthenticated binds (RFC 4513), StartTLS stripping (a refused/continued-cleartext StartTLS), directory enumeration (whole-subtree objectClass=* / sweeps — BloodHound-style), sensitive-attribute reads (userPassword / LAPS / gMSA / SPN / ACL — Kerberoast recon), LDAP filter injection, bind brute force / spraying, and CLDAP reflection/amplification.

                    
One short passive Scapy capture (LDAP 389 · GC 3268 · LDAPS 636 · GC-S 3269 · CLDAP udp/389). The BER parser is pure-Python (no library dissectors) and tolerates snaplen-truncated packets. Needs Scapy (Detector Self-Test → Install Scapy). Fix: require LDAPS/StartTLS, disable anonymous binds, enforce LDAP signing + channel binding (EPA), and restrict UDP/389 at the edge.

                    

                        
                        
                        
                    

                    

                

                
                

                    
OSPF Security Scanner

                    
Passive OSPF routing-security scanner — detection-only, never forms an adjacency, floods an LSA, or touches the LSDB. Watches the OSPF control plane for weak/no authentication (the enabler for LSA injection), anomalies (a rogue OSPF router / adjacency spoof, duplicate Router-ID, Hello mismatch), LSA injection (spoofed advertising router, MaxSequence/MaxAge, fight-back, rogue Type-5 route injection) and flooding storms. Detects vulnerabilities — it does not exploit them.

                    
One short passive capture (put the Pi on the routed VLAN or a SPAN/mirror to see OSPF). The first scan learns the current routers and Type-5 originators as the trusted baseline (data/ospf_watch.json); after a legitimate topology change, click "Trust current". EIGRP Watch (Cisco · IGP)

                    
Passive EIGRP routing-security scanner — detection-only, never forms an adjacency, sends a hello, or injects a route. EIGRP is Cisco's interior gateway protocol (the Cisco-world alternative to OSPF; IP proto 88, multicast 224.0.0.10 / ff02::a). Without an HMAC key-chain, any host on the segment can peer and inject Update packets with attractive metrics to blackhole/MITM traffic. Unlike OSPF, tcpdump decodes EIGRP's route TLVs, so this sees route injection directly. Flags injection (a prefix not in the baseline, or a known prefix with a new next-hop — route/next-hop hijack), rogue-router (a new EIGRP speaker), storm (hello/query flood), anomaly (K-value / AS mismatch) and weak-auth (no Authentication TLV).

                    
One short passive capture (put the Pi on the routed VLAN or a SPAN/mirror to see EIGRP). The first scan learns the current routers and advertised prefix→next-hop map as the baseline (data/eigrp_watch.json); after a legitimate topology change, click "Trust current". IPv4 route TLVs are fully decoded; IPv6 EIGRP gives speaker/AS/auth/K-values (per-prefix v6 TLVs aren't dissected by tcpdump).

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
IS-IS Watch (IGP · ISP/DC core)

                    
Passive IS-IS routing-security scanner — detection-only, never forms an adjacency or injects an LSP. IS-IS (ISO 10589) is the third interior gateway protocol alongside OSPF and EIGRP, and the one that dominates ISP / service-provider and data-center cores. It runs directly on L2 (LLC DSAP 0xFE) — not over IP — so IP ACLs don't touch it; its only real protection is TLV-10 authentication. Without it, any host can peer and inject LSPs with attractive metrics to blackhole/MITM traffic. tcpdump decodes the reachable prefixes, so this sees injection directly. Flags injection (an LSP from a new system-id, or a new/re-homed prefix), rogue-router (a new IS-IS speaker), storm (hello/LSP flood), anomaly (duplicate system-id / new area) and weak-auth (no auth or cleartext password).

                    
One short passive capture on the IS-IS multicast MACs (AllL1ISs 01:80:c2:00:00:14 + AllL2ISs 01:80:c2:00:00:15). The first scan learns the current routers — resolved to names via the dynamic-hostname TLV — their areas, and the advertised prefix→originator map as the baseline (data/isis_watch.json); after a legitimate topology change, click "Trust current".

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
FHRP Watch (HSRP · VRRP · GLBP · CARP)

                    
Passive First-Hop-Redundancy-Protocol hijack scanner — detection-only, never sends an FHRP packet or joins an election. FHRP (HSRP/VRRP/GLBP/CARP) lets routers share one virtual gateway IP+MAC and picks the active router by priority; the hellos are multicast in the clear with weak/no auth. An attacker who sees them can inject a forged priority-255 hello + preempt, win the election, and become everyone's default gateway (subnet-wide MITM, e.g. Yersinia/Loki). Flags hijack (a new speaker advertising a winning priority, or an HSRP Coup), rogue-speaker (a new speaker not yet winning), priority-change (a known speaker's priority jumped) and weak-auth (plaintext/no FHRP auth — the enabler). GLBP is watched on both of its election planes: the AVG (Active Virtual Gateway — winning it is worse than HSRP, the attacker picks who to MITM) via the priority rules, plus the AVF forwarder plane — glbp-avf-hijack (a non-owner going Active for a forwarder / seizing its virtual MAC = a stealth per-slice MITM while the gateway election looks healthy) and glbp-weight-skew (a load-share shift that steers hosts onto/off an AVF).

                    
One short passive capture on the routed segment (HSRP udp/1985, GLBP udp/3222, VRRP+CARP IP-proto-112). The first scan learns the current groups, active speakers/priorities, and GLBP forwarders as the trusted baseline (data/fhrp_watch.json); after a legitimate router/priority change, click "Trust current". HSRP+VRRP are decoded via tcpdump; GLBP is decoded by a hand-rolled byte parser (neither tcpdump nor Scapy dissects it) that reads the AVG priority, forwarder numbers, virtual MACs and weights; CARP is best-effort.

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
BGP Path Watch

                    
Passive BGP routing-security scanner — detection-only, never opens a session or announces/withdraws a route. The L3-edge companion to the OSPF scanner. Watches for prefix / origin hijacks and sub-prefix hijacks (origin-AS change vs baseline), anomalies (rogue peer, session reset/NOTIFICATION, bogon/martian prefix, reserved ASN, AS-path loop, BLACKHOLE community), route-leak storms, and weak session security (no TCP-MD5/TCP-AO). Detects — never exploits.

                    
BGP is unicast TCP/179 between routers, so the Pi must be inline, on a SPAN/mirror, or a peer to observe it (unlike OSPF, it's not on the broadcast domain). The first scan learns the current peers and prefix→origin map as the baseline (data/bgp_watch.json); "Trust current" re-learns. Version CVEs aren't visible on the wire — exposure conditions are flagged with OSV pointers. ASNs are enriched with owner names via Team Cymru (outbound TCP/43; soft-fails to AS-number-only if egress filters it).

                    

                        
                        
                        
                        
                    

                    

                

                
                

                    
BGP Collector & Path Asymmetry (control-plane ↔ data-plane)

                    
Receive-only — the collector opens a passive BGP session to learn the peer's RIB but never advertises or withdraws a route. Pairs the routing truth (which AS should originate a prefix, whether it's flapping) with a measured one-way-delay probe, so a path-asymmetry event can be attributed to a real routing change vs. a pure data-plane shift.

                    
Point the collector at a router willing to peer (configure the Pi's AS as a passive/route-server client). Run the OWD reflector on the far node (or here) so the other side can measure delay in both directions; asymmetry uses the Paxson min-pair estimator to cancel clock offset, so it reports change-sensitive asymmetry unless both clocks are PTP/GPS-synced. Events are correlated against the live RIB when the collector is Established.
