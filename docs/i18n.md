# Languages

Ragnar's web interface and its AI answers are available in English, Spanish
(Español), French (Français) and German (Deutsch).

## Changing the language

Open **Config > System** and pick a language in the **Language** card. The page
switches immediately, without a reload. The choice is saved on the unit, so:

- every browser open on that unit switches too, and new pages (including the
  login page, the captive portal / Wi-Fi setup pages and the phone wardriving
  page) open in that language;
- every AI answer is written in that language: the dashboard AI insights, the
  Wi-Fi and WiFi Defense analyses, PCAP analysis, the Signal Analyzer assistant
  and the chat assistant. Dashboard insights regenerate in the new language on
  their own. A result that was already on screen stays as it was until you run
  that analysis again.

The setting is part of **Fleet Config** export/import, so a fleet can share one
language.

## What stays as it is

- Data from the network and devices: hostnames, SSIDs, vendors, banners, file
  names, alert evidence.
- The unit's own log lines in the Activity Log (your UI actions are translated),
  the web terminal, command output, code and commands.
- Machine-readable AI output: device classification, and the keys, phases,
  actions and tools of an AI-generated Engagements playbook (its name and
  description follow the language).

## How it works

The UI source stays English. `web/scripts/i18n.js` translates the live page: it
watches the DOM and swaps each English text node and translatable attribute
(`title`, `placeholder`, `aria-label`, `alt`, `data-tooltip`, `data-label`) for
the active language, using the packs in `web/scripts/i18n/<lang>.json`. Packs map
the English source text to its translation:

- plain text: `"Check for Updates": "Buscar actualizaciones"`
- text built at runtime, with `{0}`, `{1}` for the dynamic parts:
  `"Found {0} hosts": "Se encontraron {0} equipos"`
- a sentence with inline markup (`<strong>`, `<a>`, `<code>`, `<br>`...), where
  `{n}` is the n-th child element: `"Click {0} to continue"`

Anything without an entry stays English. Subtrees marked `translate="no"` or
`class="notranslate"`, and `<code>`, `<pre>`, `<textarea>`, `<kbd>`, `<samp>` and
the terminal, are never touched.

The server keeps the setting as `language` in the config (`en`, `es`, `fr`,
`de`):

| Endpoint | Purpose |
|---|---|
| `GET /api/i18n/language` | Current language (public, so the login page can use it) |
| `POST /api/i18n/language` `{"language": "es"}` | Change it (login required); pushes `language_changed` to every open page |
| `GET /scripts/i18n/active.js` | The active pack, loaded in `<head>` so pages render translated from the first paint |
| `GET /scripts/i18n/<lang>.json` | One pack, fetched when switching at runtime |

Prose AI prompts get a language instruction from
`ai_service.prose_language_directive`; calls whose reply is parsed as a fixed
format pass `localize=False`. AI results are cached per language.

## Writing UI code

- Keep writing UI text in English.
- Never branch on on-screen text: once translated, `el.textContent` is not
  English any more. Use `_i18nText(el)` (or `RagnarI18n.source(el)`), which
  returns the English source.
- Mark containers that show raw data with `translate="no"`.
- For text that never reaches the DOM (canvas drawing), use
  `RagnarI18n.t('English text')`. `alert`, `confirm` and `prompt` are translated
  automatically.

## Updating the language packs

The extractor finds every string the UI can show (HTML text and attributes,
JavaScript string literals, template literals and concatenations, and the
backend's API messages via `scripts/i18n/extract_backend.py`) using the same key
rules as the runtime.

```bash
npm install                      # once: acorn + htmlparser2 (dev only)
npm run i18n:check               # per language: translated / missing / unused
node scripts/i18n/extract_strings.js --missing /tmp/i18n   # <lang>.missing.json with context
node scripts/i18n/extract_strings.js --catalog /tmp/catalog.json
node scripts/i18n/extract_strings.js --prune                # drop unused entries
```

Translate the missing keys, keep every `{n}` placeholder exactly once, and add
them to the pack. `tests/test_i18n.py` checks every pack (valid JSON, placeholders
intact, no stray whitespace, all packs covering the same keys).

## Adding a language

Add the code in `SUPPORTED` / `NATIVE_NAMES` (`web/scripts/i18n.js`),
`UI_LANGUAGES` (`webapp_modern.py`), `RESPONSE_LANGUAGES` (`ai_service.py`) and
`LANGS` (`scripts/i18n/extract_strings.js`), add an `<option>` to the Language
card in `web/index_modern.html`, then create `web/scripts/i18n/<code>.json`.
